# کارت دعوت 💌

یک اپ تک‌کامپوننتی React برای ساخت کارت دعوت — موبایل‌فرست، RTL، با گلس‌مورفیسم و انیمیشن‌های Framer Motion.

**۱۰ قالب آماده**، رنگ‌بندی قابل تغییر توسط کاربر، اشتراک‌گذاری تلگرام و واتس‌اپ، و
موقعیت مکانی روی نشان / ویز / گوگل‌مپ.

فایل اصلی: [`DateProposalApp.jsx`](./DateProposalApp.jsx) — همه‌چیز در یک کامپوننت.

## راه‌اندازی از صفر

این مراحل عیناً تست شده‌اند (Vite 8 + React 19 + Tailwind 4). از هر پوشه‌ای:

```bash
npm create vite@latest my-date -- --template react
cd my-date
npm install
npm i framer-motion
npm i -D tailwindcss @tailwindcss/vite
```

بعد `DateProposalApp.jsx` را در `src/` بگذار و این چهار فایل را ویرایش کن:

**`vite.config.js`** — پلاگین Tailwind را اضافه کن:

```js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({ plugins: [react(), tailwindcss()] })
```

**`src/index.css`** — کل محتوا فقط همین یک خط (بقیه‌اش را پاک کن):

```css
@import "tailwindcss";
```

**`src/App.jsx`**:

```jsx
import DateProposalApp from './DateProposalApp.jsx'

export default function App() {
  return <DateProposalApp />
}
```

**`index.html`** — برای RTL و عنوان تب:

```html
<html lang="fa" dir="rtl">
...
<title>پایه‌ای بریم سر قرار؟ 💖</title>
```

> `src/App.css` را پاک کن — استایل پیش‌فرض Vite با لایه‌بندی کامپوننت قوز بالا قوز می‌کند.

```bash
npm run dev     # http://localhost:5173
```

## انتشار روی سایت

```bash
npm run build   # خروجی در dist/
```

`dist/` یک سایت استاتیک ساده است (۵ فایل، حدود ۲۳۰KB) — نه PHP، نه دیتابیس، نه Node
روی سرور. هر جایی بالا می‌رود.

### دو تنظیم که بدون آن‌ها می‌شکند

**۱. `base: './'` در `vite.config.js`**

```js
export default defineConfig({ base: './', plugins: [react(), tailwindcss()] })
```

با این، مسیر دارایی‌ها نسبی می‌شود و build **در هر زیرپوشه‌ای** کار می‌کند
(`site.com/kart/`، `site.com/a/b/c/`) بدون اینکه کانفیگ را عوض کنی. بدون آن، مسیرها
از ریشه‌ی دامنه خوانده می‌شوند و در زیرپوشه صفحه سفید می‌آید.

**۲. فونت را داخل build ببر، نه از CDN**

```jsx
import fontUrl from 'vazirmatn/fonts/webfonts/Vazirmatn[wght].woff2?url'

<InviteCard fontUrl={fontUrl} />
```

دو دلیل: اول اینکه دسترسی به jsDelivr از ایران قابل‌اتکا نیست؛ دوم اینکه اگر فونت را
دستی با مسیر مطلق (`/Vazirmatn...`) بدهی، در زیرپوشه ۴۰۴ می‌گیرد. با `import`،
Vite خودش مسیر درست و نسبی را می‌سازد.

نتیجه: build صفر درخواست به دامنه‌ی خارجی می‌زند — کاملاً آفلاین بالا می‌آید.

### روی هاست خودت (cPanel / FTP / دایرکت‌ادمین)

محتوای `dist/` را در پوشه‌ی دلخواه آپلود کن:

```
public_html/kart/      →  https://yoursite.com/kart/
```

همین. چون مسیریابی روی **hash** است، **هیچ rewrite rule ای لازم نیست** —
نه `.htaccess`، نه تنظیم nginx. لینک‌های ساخته‌شده هم زیرپوشه را نگه می‌دارند.

### کنار وردپرس

اپ به وردپرس کاری ندارد و لازم نیست پلاگین بشود. پوشه را کنار وردپرس بگذار:

```
public_html/            ← وردپرس
public_html/kart/       ← کارت دعوت
```

اگر می‌خواهی داخل یک برگه‌ی وردپرسی هم دیده شود، iframe کافی است:

```html
<iframe src="/kart/" style="width:100%;height:100vh;border:0" loading="lazy"></iframe>
```

### Vercel / Netlify / GitHub Pages

- **Vercel / Netlify** — ریپو را وصل کن، خودش Vite را می‌شناسد. صفر کانفیگ.
- **GitHub Pages** — با `base: './'` بالا، دیگر لازم نیست `base` را با نام ریپو ست کنی.

از موبایل بی‌مشکل باز می‌شود؛ کل UI موبایل‌فرست است و در ویوپورت ۳۹۰px تست شده.

## فونت وزیرمتن

کامپوننت خودش `@font-face` وزیرمتن را یک‌بار به `<head>` تزریق می‌کند — نیازی به دست‌زدن به `index.html` نیست.

نسخه‌ی **variable** استفاده می‌شود: یک فایل ~۱۱۱KB که کل وزن‌های ۱۰۰ تا ۹۰۰ را می‌دهد
(کامپوننت از ۴۰۰ تا ۹۰۰ استفاده می‌کند) — یعنی یک درخواست شبکه به‌جای شش تا.

با `font-display: swap`؛ اگر فونت لود نشود متن بلافاصله با استک
`Vazirmatn → Vazir → IRANSans → IRANYekan → Tahoma` رندر می‌شود و چیزی نمی‌شکند.

### میزبانی محلی (آفلاین / پروداکشن)

```bash
npm i vazirmatn
```

```jsx
import fontUrl from "vazirmatn/fonts/webfonts/Vazirmatn[wght].woff2?url"; // Vite

<DateProposalApp fontUrl={fontUrl} />
```

`fontUrl={null}` تزریق فونت را کامل خاموش می‌کند (اگر خودت گلوبال ست کرده‌ای).

## بدون وابستگی اضافه

سه چیزی که معمولاً پکیج جدا می‌خواهند، اینجا بومی پیاده‌سازی شده‌اند:

|---|---|

### قالب فقط رنگ نیست، رفتار است

این مهم‌ترین تصمیم معماری این فایل است. اگر قالب فقط پالت رنگ را عوض می‌کرد،
کارت **سوگ** با کانفتی، قلب‌های شناور، دکمه‌ی فراری «نچ» و لحن «پایه‌ای؟» بالا
می‌آمد — که توهین‌آمیز است. پس هر قالب سه فلگ رفتاری دارد:

- **`playful`** — شوخیِ دکمه‌ی فراری «نه». خاموش که باشد، «نه» یک دکمه‌ی واقعی
  است و به صفحه‌ی رد محترمانه می‌رود (نه اینکه کاربر گیر کند).
- **`celebrate`** — کانفتی، ایموجی‌های شناور، و افکت صوتی. در کاری/جلسه/سوگ خاموش.
- **`fixedWhen`** — در عروسی، عقد، جلسه و سوگ **فرستنده** زمان را تعیین می‌کند و
  مخاطب فقط حضورش را اعلام می‌کند. در عشقی/دوستی/کاری برعکس، مخاطب زمان را
  انتخاب می‌کند. جریان اپ بر همین اساس ساخته می‌شود، برای همین تعداد مراحل
  بین ۲ تا ۴ فرق می‌کند.

در قالب‌های رسمی اسم مخاطب به تیتر چسبانده نمی‌شود («سارا، مراسم یادبود» غلط
است) — خطاب سطر جداست: «سارا عزیز،» و بعد عنوان.

## سه نام روی هر کارت

هر کارت سه چیز جدا دارد که قاطی‌کردنشان اشتباه رایج است:

| | چیست | مثال در سوگ | مثال در عروسی |
|---|---|---|---|
| **موضوع** | کارت **درباره‌ی چه کسی** است | نام متوفی | نام عروس و داماد |
| **مخاطب** | کارت **برای چه کسی** فرستاده می‌شود | نام مدعو | نام مهمان |
| **فرستنده** | **چه کسی** می‌فرستد | نام خانواده | نام خانواده / میزبان |

برچسب هر سه از روی قالب عوض می‌شود — «نام و نام خانوادگی متوفی» در سوگ،
«نام و نام خانوادگی عروس و داماد» در عروسی، «موضوع جلسه» در جلسه، و
«به مناسبتِ (اختیاری)» در قالب‌های خودمانی.

موضوع، وقتی پر شود، **عنوان کارت را می‌سازد**:

| قالب | ورودی | عنوان کارت |
|---|---|---|
| سوگ | شادروان حاج محمود محمدی | مراسم ختمِ شادروان حاج محمود محمدی |
| عروسی | سارا محمدی و رضا احمدی | مراسم عروسیِ سارا محمدی و رضا احمدی |
| عقد | سارا محمدی و رضا احمدی | جشن عقدِ سارا محمدی و رضا احمدی |
| تولد | سارا محمدی | تولدِ سارا محمدی |
| جلسه | بررسی نقشه راه محصول | جلسهٔ بررسی نقشه راه محصول |

اولویت عنوان: متن دستی کاربر ← عنوان ساخته‌شده از موضوع ← متن پیش‌فرض قالب.
پس موضوعِ خالی رفتار قبلی را دست‌نخورده نگه می‌دارد.

موضوع در بلیط هم یک ردیف اختصاصی می‌گیرد («🕊️ مرحوم/مرحومه»، «💍 عروس و داماد»،
«🎂 صاحب تولد»، …) و در متن پاسخی که مخاطب می‌فرستد هم می‌آید.

## رنگ‌بندی

۱۰ پالت آماده + انتخابگر رنگ دلخواه. هر قالب پالت پیش‌فرض خودش را دارد و کاربر
می‌تواند عوضش کند. رنگ دوم گرادیان از روی رنگ انتخابی کاربر خودکار ساخته می‌شود.

تم با CSS variable روی ریشه پیاده شده (`--accent`، `--accent2`، `--ink`، `--muted`،
`--bg1..3`)، نه با کلاس‌های داینامیک Tailwind — چون کلاس ساخته‌شده در زمان اجرا
را اسکنر Tailwind نمی‌بیند و در build حذف می‌شود.

مقدار رنگ دلخواه قبل از استفاده اعتبارسنجی می‌شود (`#rrggbb`)؛ هر چیز دیگری
نادیده گرفته می‌شود و پالت پیش‌فرض می‌ماند.

## موقعیت مکانی

فیلد لوکیشن هم آدرس متنی می‌گیرد هم لینک نقشه. اگر لینک نشان/گوگل‌مپ/ویز پیست
کنی، مختصات خودکار از آن بیرون کشیده می‌شود.

مخاطب سه دکمه می‌بیند: **نشان**، **Waze**، **گوگل‌مپ**. با مختصات، لینک مستقیم به
همان نقطه می‌رود؛ بدون مختصات، جستجوی متنی.

## اشتراک‌گذاری

هم تلگرام هم واتس‌اپ، در دو جا: فرستنده لینک را می‌فرستد، مخاطب جواب را برمی‌گرداند.

یک تفاوت واقعی بین این دو که در کد لحاظ شده: **واتس‌اپ متن را برای یک شماره‌ی
مشخص پیش‌پر می‌کند** (`wa.me/<phone>?text=`)، ولی **تلگرام این کار را نمی‌کند** —
فقط share sheet را پیش‌پر می‌کند. برای همین وقتی آیدی تلگرام داده شده، متن کپی
می‌شود و چت باز می‌شود، با راهنمای «تو چت پیستش کن».

شماره‌ی موبایل به فرمت بین‌المللی نرمال می‌شود: `09121234567` → `989121234567`.

## حالت ساخت لینک

باز کردن اپ بدون hash، صفحه‌ی **ساخت کارت** را می‌آورد: قالب، رنگ‌بندی، اسم‌ها،
سوال دلخواه، پیام شخصی، تاریخ (در قالب‌های زمان‌ثابت)، لوکیشن، تلگرام و واتس‌اپ.
لینک همان‌طور که تایپ می‌کنی ساخته می‌شود.

مخاطب که لینک را باز کند، مستقیم می‌رود سر دعوت — شخصی‌سازی‌شده با اسم خودش.

```
https://your.site/#c=eyJ0Ijoi2LPYp9ix2KciLCJmIjoi2LHYttinIn0
```

**همه‌چیز در خودِ لینک است** — نه دیتابیس، نه بک‌اند، نه اکانت. کانفیگ به‌صورت
JSON فشرده (کلیدهای تک‌حرفی) با base64url داخل hash کد می‌شود. یک کارت معمولی
حدود ۱۶۰ کاراکتر لینک می‌دهد.

چند نکته‌ی عمدی در طراحی:

- **hash، نه query string.** بخش بعد از `#` اصلاً به سرور فرستاده نمی‌شود، پس پیام
  شخصی توی لاگ سرور و هدر Referer نمی‌نشیند. روی هاست استاتیک هم بدون کانفیگ کار می‌کند.
- **اگر آیدی تلگرام بدهی، جواب برمی‌گردد به خودت.** دکمه‌ی آخر می‌شود «جوابو بفرست
  به @you»؛ متن را کپی می‌کند و چت خودت را باز می‌کند. (تلگرام اجازه‌ی پیش‌پرکردن پیام
  برای یک کاربر مشخص را نمی‌دهد، فقط share sheet را — برای همین کپی + باز کردن چت.)
- **لینک خراب صفحه‌ی سفید نمی‌دهد.** هر ورودی نامعتبر برمی‌گردد به صفحه‌ی ساخت.

## جریان اپ

ساخت کارت → دعوت → (انتخاب زمان، اگر قالب اجازه بدهد) → (گزینه‌ها، اگر قالب داشته باشد) → کارت نهایی و فرستادن جواب.

مراحل از روی قالب ساخته می‌شوند، پس بین ۲ تا ۴ مرحله متغیر است.

## نکته‌ی طراحی: دکمه‌ی «نه» (فقط در قالب‌های بازیگوش)

دکمه ابتدا خاکستری و «خرابه» است، با تولتیپ طعنه‌آمیز؛ بعد فرار می‌کند و در تلاش پنجم تسلیم می‌شود و به «آره دیگه 💖» تبدیل می‌شود.

پنج طعنه به‌ترتیب نشان داده می‌شوند و آخری («اوکی بردی 🥲 کردمش «آره»») دقیقاً لحظه‌ی تبدیل می‌آید.

دو نکته‌ی ظریف که در پیاده‌سازی رعایت شده:

- **روی موبایل hover وجود ندارد.** اگر منطق فقط به hover و کلیکِ دقیق روی دکمه‌ی متحرک وابسته باشد، کاربر موبایل ممکن است هیچ‌وقت به مرحله‌ی تبدیل نرسد. برای همین یک «منطقه‌ی شکار» با ارتفاع ثابت دور دکمه هست که تپِ خطا رفته را هم به‌عنوان تلاش حساب می‌کند.
- **تپِ تبدیل‌کننده، فرم را ثبت نمی‌کند.** بعد از تبدیل، ۹۰۰ms کلیک نادیده گرفته می‌شود تا کاربر لحظه‌ی «نچ → آره» را ببیند.

جابه‌جایی دکمه هم عمداً داخل عرض کارت محدود شده تا زیر `overflow-hidden` بریده و غیرقابل‌لمس نشود.
