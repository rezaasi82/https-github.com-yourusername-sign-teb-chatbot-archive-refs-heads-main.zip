# گزارش عملکرد — SignTeb MedCore (فاز ۷)

## بیانیه‌ی صادقانه

عدد نهایی PageSpeed (۹۵ دسکتاپ / ۹۰ موبایل) فقط با **تست میدانی روی سرور واقعی**
قابل اثبات است و به عواملی خارج از قالب هم بستگی دارد: زمان پاسخ سرور/هاست،
افزونه‌ی کش، CDN، بهینه‌سازی تصاویر، و نسخه‌ی PHP. این گزارش کارهای **سمت‌کدِ
قالب** را که انجام و تست شده‌اند مستند می‌کند — یعنی موانع کدی که در کنترل قالب
هستند برطرف شده‌اند. عدد ۹۵/۹۰ را ادعا نمی‌کنیم؛ زیرساخت کدی برای رسیدن به آن
آماده است.

## بهینه‌سازی‌های موجود (از قبل در قالب)

- **بارگذاری شرطی دارایی‌ها:** JS/CSS اسلایدر قبل/بعد فقط در صفحات پزشک لود می‌شود.
- **defer روی JS:** اسکریپت‌های اصلی با `defer` (بدون render-blocking).
- **Critical CSS درون‌خطی** در `<head>` + بارگذاری CSS غیربحرانی با ترفند `media="print"`/`onload`.
- **preload فونت‌های بحرانی** (Vazirmatn) + فونت self-hosted (بدون درخواست خارجی).
- **حذف jQuery از فرانت** (وقتی افزونه‌ای نیازش ندارد).
- **`loading="lazy"` + width/height** روی تصاویر بلوک‌ها (کاهش CLS).

## معماری

`SignTeb\MedCore\Performance\Optimizer` — بوت‌شده از طریق Container، فقط روی فرانت
اعمال می‌شود و پیشخوان را دست‌نخورده می‌گذارد. تمام هوک‌ها در try/catch ایزوله
هستند تا هرگز باعث صفحه‌ی سفید نشوند.

## تأیید

تست end-to-end: هوک‌ها درست ثبت شدند، حذف ایموجی/generator/rsd تأیید شد، سوییچ به
`.min.css` فقط وقتی فایل موجود است انجام می‌شود (با guard ضدِ ۴۰۴)، و handleهای
غیرمرتبط دست‌نخورده می‌مانند. `php -l` بدون خطا.

## توصیه‌های تکمیلی (خارج از قالب — برای رسیدن به ۹۵/۹۰)

1. نصب یک **افزونه‌ی کش** (مثل WP Super Cache / LiteSpeed Cache).
2. **بهینه‌سازی تصاویر** (WebP + فشرده‌سازی) — به‌خصوص تصاویر واقعیِ جایگزین دموها.
3. فعال‌سازی **HTTP/2 + gzip/brotli** روی سرور.
4. استفاده از **CDN** برای دارایی‌های استاتیک.
5. هاست با **PHP 8.1+** و OPcache فعال.
