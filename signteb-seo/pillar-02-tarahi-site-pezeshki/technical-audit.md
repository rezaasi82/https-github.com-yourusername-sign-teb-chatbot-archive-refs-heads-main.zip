# ممیزی فنی — پیلار «طراحی سایت پزشکی»

تاریخ: ۲۰۲۶-۰۸-۰۶ · روش: بررسی HTML زنده signteb.com + شمارش مستقیم از کدبیس MedCore

## ۱. 🔴 مهم‌ترین یافته: بخش زیادی از این Master Prompt از قبل ساخته شده است

`/medical-website-design-examples/` یک صفحه تقریباً کامل است، نه صرفاً یک گالری ساده. محتوای واقعی آن:

| بخش موجود | وضعیت |
|---|---|
| گالری فیلترشونده | ✅ **از قبل هست** — ۵ فیلتر: همه پروژه‌ها / پزشک متخصص / چندزبانه / محتوا و برندینگ / سایر صنایع |
| تعداد پروژه | ۲۱ پروژه با عنوان و توضیح اختصاصی |
| بخش مزایای MedCore | ✅ **از قبل هست** — Schema پزشکی خودکار، RTL بومی، سرعت بارگذاری، اعتمادسازی |
| فرآیند کار | ✅ **از قبل هست** — و **۵ مرحله‌ای** است، نه ۴ مرحله‌ای |
| کیس‌استادی | ✅ بلوک «کلینیک چندتخصصی: از چالش تا راه‌حل» |
| تستیمونیال ستاره‌دار | ✅ موجود |
| آمار | ۱۷ سال تجربه · ۲۵ سال مدیریت روابط بیمارستانی · صدها پروژه · ۳۵ پروژه فعال |
| Title فعلی | «نمونه کار طراحی سایت پزشکی VIP | +۳۵ پروژه فعال SignTeb (ایران و دبی)» |
| H1 فعلی | «نمونه کار طراحی سایت پزشکی SignTeb برای پزشکان، جراحان و کلینیک‌های VIP» |

**پیامد:** اگر پیلار جدید هم گالری، هم مزایای MedCore و هم فرآیند کار را از نو بسازد، عملاً یک نسخه دوم از همین صفحه می‌شود و هر دو همدیگر را در گوگل خنثی می‌کنند.

خوشبختانه خود Master Prompt در بند ۴ نوشته «لینک/Embed از صفحه نمونه طراحی سایت موجود» — همین مسیر درست است و در `content.md` رعایت شده.

### دو گزینه — تصمیم با شماست

**گزینه A — بدون صفحه جدید (کم‌ریسک‌ترین).**
همان `/medical-website-design-examples/` را به پیلار تبدیل کنید: Title و H1 را از «نمونه کار طراحی سایت پزشکی» به «طراحی سایت پزشکی» تغییر دهید و دو بخش تجاری (چرا نه سایت‌ساز رایگان + هزینه) را به آن اضافه کنید. URL و اعتبار فعلی حفظ می‌شود و هیچ صفحه رقیبی ساخته نمی‌شود.

**گزینه B — صفحه جدید با تقسیم کار روشن (پیاده‌سازی‌شده در این پکیج).**
`/tarahi-site-pezeshki/` صفحه **فروش** می‌شود و `/medical-website-design-examples/` صفحه **اثبات** باقی می‌ماند:

| صفحه | کلمه هدف | نقش | چه چیزی دارد |
|---|---|---|---|
| `/tarahi-site-pezeshki/` (جدید) | طراحی سایت پزشکی، طراحی سایت دکتر، قیمت طراحی سایت پزشکی | Commercial | چرا نه سایت‌ساز رایگان · مزیت فنی · هزینه · FAQ |
| `/medical-website-design-examples/` (موجود) | نمونه کار طراحی سایت پزشکی، نمونه سایت دکتر | Proof | گالری ۲۱ پروژه · فرآیند ۵ مرحله‌ای · کیس‌استادی |

در گزینه B این قواعد **الزامی** است تا cannibalization رخ ندهد:
1. پیلار جدید گالری را **بازسازی نکند** — فقط ۶ پروژه منتخب به‌صورت teaser + دکمه «مشاهده کامل گالری».
2. پیلار جدید فرآیند کار را تکرار نکند — به بخش فرآیند صفحه نمونه‌کار لینک دهد.
3. Title صفحه نمونه‌کار روی «نمونه کار» متمرکز بماند و عبارت «طراحی سایت پزشکی» به‌عنوان کلمه اصلی از آن حذف/کم‌رنگ شود.
4. لینک دوطرفه بین دو صفحه با انکرهای متفاوت.

> `content.md` و `gutenberg.html` این پکیج بر اساس **گزینه B** نوشته شده‌اند. اگر گزینه A را انتخاب کردید، فقط بخش‌های «چرا سایت‌ساز رایگان کافی نیست» و «هزینه» و «FAQ» را از `content.md` بردارید و به صفحه موجود اضافه کنید.

## ۲. تصحیح ادعای فنی: MedCore ۸ نوع محتوا دارد، نه ۹

Master Prompt بند ۱ نوشته «۹ CPT». شمارش مستقیم از کد (`register_post_type` در `signteb-medical-core/includes/post-types/`) عدد **۸** می‌دهد:

`doctor` · `clinic` · `medical-service` · `treatment` · `disease` · `case-study` · `medical-video` · `medical-faq`

به‌علاوه **۴ تاکسونومی**: `specialty` · `condition` · `location` · `treatment-type`

**چون این صفحه ادعای برتری فنی می‌کند، عدد اشتباه بدترین جای ممکن برای اشتباه است.** در `content.md` از اعداد راستی‌آزمایی‌شده استفاده شده و برای پرهیز از شمارش‌های شکننده، بیشتر روی قابلیت‌ها تأکید شده تا روی عدد.

## ۴. 🟡 مشکل ساختاری منو (روی هر ۴ پیلار اثر دارد)

آیتم‌های زیرمنوی «دیجیتال مارکتینگ» به‌جای صفحات سرویس، به **آرشیو دسته‌بندی وبلاگ** می‌روند و آن هم روی **`http://`** نه `https://`:

```
طراحی هویت بصری   -> http://signteb.com/category/طراحی-هویت-بصری/
تولید محتوا پزشکی -> http://signteb.com/category/تولید-محتوا-پزشکی/
```

دو مشکل همزمان: (۱) کاربر با نیت خرید به آرشیو وبلاگ می‌رسد، (۲) هر کلیک یک ریدایرکت اضافه `http→https` می‌خورد که هم کند است و هم کمی از اعتبار لینک را هدر می‌دهد.

**اقدام:** پس از ساخت هر پیلار، آیتم منوی متناظر به آن صفحه با `https://` تغییر کند.
