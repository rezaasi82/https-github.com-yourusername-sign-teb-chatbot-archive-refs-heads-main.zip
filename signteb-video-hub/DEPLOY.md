# راه‌اندازی SignTeb Video Hub

سه مرحله: ساخت بسته، نصب روی سایت، و (اختیاری) زمان‌بندی بیرونی همگام‌سازی.

---

## ۱. ساخت بسته‌ی قابل نصب

```bash
cd signteb-video-hub
make zip
```

خروجی: `build/signteb-video-hub-<نسخه>.zip` (حدود ۱۷۰ کیلوبایت).

`make zip` قبل از بسته‌بندی، بررسی نحوی و تست‌ها را اجرا می‌کند و اگر چیزی خطا داشته باشد بسته ساخته نمی‌شود. فایل‌های توسعه (`tests/`, `Makefile`, `composer.json`) داخل بسته نمی‌روند.

دستورهای دیگر:

| دستور | کار |
|---|---|
| `make check` | بررسی نحوی + تست‌ها — قبل از هر کامیت |
| `make lint` | فقط بررسی نحوی |
| `make test` | فقط تست‌ها (۵۶ assertion) |
| `make clean` | پاک کردن `build/` |

## ۲. نصب روی وردپرس

1. پیشخوان ← **افزونه‌ها ← افزودن ← بارگذاری افزونه** ← فایل ZIP را انتخاب کنید.
2. **فعال‌سازی** کنید. جدول‌ها، موضوعات پیش‌فرض و زمان‌بندی cron خودکار ساخته می‌شوند.
3. **ویدئو هاب ← تنظیمات** → شناسه کانال آپارات را وارد کنید (`mychannel`).
4. دکمه‌ی **تست اتصال** را بزنید — این اولین راستی‌آزمایی واقعی اتصال به API آپارات است.
5. **ویدئو هاب ← داشبورد ← همگام‌سازی دستی**.

پس از اولین همگام‌سازی موفق، آدرس‌های `/videos/` و `/videos/{موضوع}/` فعال می‌شوند. اگر ۴۰۴ گرفتید، **تنظیمات ← پیوندهای یکتا** را باز کنید و بدون تغییر ذخیره کنید تا rewrite rules بازسازی شوند.

### فعال‌سازی هوش مصنوعی (اختیاری)

در همان صفحه‌ی تنظیمات، بخش «هوش مصنوعی»: سرویس‌دهنده را انتخاب، کلید API را وارد و «تولید محتوای هوشمند» را فعال کنید. محتوا در پس‌زمینه و به‌صورت دسته‌ای تولید می‌شود (پیش‌فرض ۳ کار در هر اجرای cron)، نه یکجا.

**انتخاب سرویس‌دهنده روی هاست ایران:** روی بیشتر هاست‌های داخلی، `api.openai.com` و `api.anthropic.com` در دسترس نیستند و اتصال مستقیم با خطای شبکه شکست می‌خورد — این مشکل تنظیمات نیست و با هیچ کلیدی حل نمی‌شود.

| سرویس‌دهنده | آدرس پایه | مناسب برای |
|---|---|---|
| **GapGPT** | خودکار (`api.gapgpt.app/v1`) | هاست ایران — هم مدل‌های GPT و هم Claude را سرو می‌کند |
| Anthropic | مستقیم | سرور خارج از ایران |
| سازگار با OpenAI | دستی وارد کنید | هر درگاه سازگار دیگر |

برای GapGPT فیلد «آدرس پایه سرویس» را **خالی** بگذارید؛ آدرس پیش‌فرض خودکار استفاده می‌شود. بعد از وارد کردن کلید، دکمه‌ی **تست اتصال** کنار همان بخش را بزنید.

> محتوای تولیدشده باید پیش از انتشار توسط پزشک بازبینی شود. پیشنهاد مقاله همیشه پیش‌نویس می‌ماند.

## ۳. زمان‌بندی بیرونی همگام‌سازی (اختیاری)

**چرا لازم است:** WP-Cron وردپرس یک زمان‌بند واقعی نیست — فقط وقتی اجرا می‌شود که کسی از سایت بازدید کند. روی سایت کم‌ترافیک، «همگام‌سازی خودکار هر ۶ ساعت» ممکن است بی‌صدا اجرا نشود.

دو راه وجود دارد. **گزینه‌ی الف بهتر است** اگر به سرور دسترسی دارید.

### الف) کرون واقعی سرور (رایگان، مطمئن‌تر)

در `wp-config.php`:

```php
define('DISABLE_WP_CRON', true);
```

سپس در cPanel ← Cron Jobs (هر ۶ ساعت):

```
0 */6 * * * curl -s https://example.com/wp-cron.php?doing_wp_cron > /dev/null
```

این کل زمان‌بندی وردپرس را درست می‌کند، نه فقط این افزونه را.

### ب) سناریوی Make.com

سناریو از قبل ساخته شده است:

- **نام:** SignTeb Video Hub — همگام‌سازی زمان‌بندی‌شده
- **شناسه:** `5792346`
- **بازه:** هر ۶ ساعت (۲۱۶۰۰ ثانیه)
- **وضعیت:** **غیرفعال** — تا وقتی رمز را وارد نکنید فعالش نکنید
- **مصرف:** حدود ۱۲۰ عملیات در ماه از سهمیه‌ی ۱۰۰۰تایی پلن رایگان

**برای فعال کردن:**

1. در وردپرس: **کاربران ← پروفایل شما ← Application Passwords**. یک رمز جدید با نام `Make Sync` بسازید و رشته‌ی تولیدشده را کپی کنید. این رمز عبور اصلی شما نیست و هر زمان قابل ابطال است.
2. در Make: سناریو را باز کنید ← روی ماژول HTTP کلیک کنید ← بخش **Advanced settings**:
   - `User name` → نام کاربری وردپرس شما (جای `REPLACE_WITH_WP_USERNAME`)
   - `Password` → رمز Application Password (جای `REPLACE_WITH_APP_PASSWORD`)
3. یک‌بار **Run once** بزنید. پاسخ موفق چنین چیزی است:
   ```json
   {"ok": true, "message": "۳ ویدئوی جدید، ۰ به‌روزرسانی، ۲۷ بدون تغییر.", "data": {...}}
   ```
4. اگر موفق بود، سناریو را **فعال** کنید.

**اگر خطای ۴۰۱ گرفتید:** بعضی هاست‌ها (Apache با CGI/FastCGI) هدر `Authorization` را حذف می‌کنند و احراز هویت هرگز به وردپرس نمی‌رسد. در `.htaccess` اضافه کنید:

```apache
SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
```

اگر باز هم کار نکرد، گزینه‌ی الف را استفاده کنید — کرون سرور اصلاً احراز هویت نمی‌خواهد.

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| «تست اتصال» آپارات خطا می‌دهد | نام کانال اشتباه است، یا هاست خروجی HTTPS به aparat.com را می‌بندد |
| ویدئوها می‌آیند ولی `/videos/` صفحه‌ی ۴۰۴ می‌دهد | rewrite rules بازسازی نشده — پیوندهای یکتا را ذخیره کنید |
| همگام‌سازی خودکار اجرا نمی‌شود | WP-Cron روی سایت کم‌ترافیک اجرا نمی‌شود — بخش ۳ را ببینید |
| محتوای هوش مصنوعی تولید نمی‌شود | کلید API وارد نشده، یا صف هنوز پردازش نشده — «پردازش صف هوش مصنوعی» را در داشبورد بزنید |
| تست اتصال هوش مصنوعی خطای شبکه/timeout می‌دهد | هاست ایران به سرویس‌دهنده‌ی مستقیم دسترسی ندارد — سرویس‌دهنده را روی GapGPT بگذارید |
| RankMath پیام «نوع پست جدید stvh_video» می‌دهد | طبیعی است — بخش زیر را ببینید |
| اسکیمای تکراری در تست گوگل | افزونه‌ی سئوی دیگری نودهای صفحه را می‌سازد — این افزونه خودکار کنار می‌کشد؛ اگر باز هم دیدید، گزارش دهید |

آخرین خطاها همیشه در **ویدئو هاب ← داشبورد ← آخرین خطاها** ثبت می‌شوند.

## پیام RankMath درباره‌ی `stvh_video`

> «Rank Math نوع جدیدی از پست را شناسایی کرده است: stvh_video…»

**این خطا نیست.** RankMath هر بار که یک نوع پست عمومی جدید ببیند این اطلاعیه را نشان می‌دهد و صرفاً می‌گوید «تنظیمات من برای این نوع پست هنوز پیش‌فرض است». اطلاعیه قابل بستن است و یک‌بار نمایش داده می‌شود.

اما دو تداخل واقعی پشتش هست که یکی‌شان را افزونه خودکار حل می‌کند و دیگری یک تنظیم دستی می‌خواهد.

### ۱. نقشه سایت تکراری — خودکار حل شده

RankMath ویدئوها را به نقشه سایت خودش اضافه می‌کند، در حالی که این افزونه `video-sitemap.xml` اختصاصی دارد. ورودی‌های RankMath تگ‌های `<video:*>` ندارند، یعنی تصویر بندانگشتی، مدت و آدرس پخش‌کننده را به گوگل نمی‌گویند — دقیقاً همان چیزهایی که ارزش سئوی ویدئو از آن‌ها می‌آید.

از نسخه‌ی ۱.۰.۱، افزونه `stvh_video` را با فیلتر `rank_math/sitemap/exclude_post_type` از نقشه سایت RankMath خارج می‌کند. اگر نقشه سایت ویدئویی را در تنظیمات خاموش کنید، این کار انجام **نمی‌شود** و ویدئوها به نقشه سایت RankMath برمی‌گردند — پس هیچ حالتی وجود ندارد که ویدئو در هیچ نقشه سایتی نباشد.

برای برگرداندن رفتار قبلی:

```php
add_filter( 'stvh_rankmath_exclude_from_sitemap', '__return_false' );
```

### ۲. اسکیمای Article اضافی — یک تنظیم دستی

RankMath برای نوع پست‌های جدید به‌صورت پیش‌فرض اسکیمای **Article** تولید می‌کند. صفحه‌ی ویدئو مقاله نیست، و این نود در کنار `VideoObject` که خود افزونه می‌سازد قرار می‌گیرد.

این را عمداً در کد حل نکردم: مقدار دقیقی که در فیلتر `rank_math/settings/snippet/type` معنی «هیچ» می‌دهد در مستندات رسمی RankMath تأیید نشده، و کدی که با نام یا مقدار حدسی هوک بزند بی‌صدا کار نمی‌کند. مسیر مطمئن، تنظیم از رابط کاربری است:

**Rank Math ← Titles & Meta ← ویدئوها ← Schema Type ← None**

بعد از این، تنها اسکیمای صفحه‌ی ویدئو همان چیزی است که این افزونه می‌سازد: `VideoObject` و در صورت وجود `FAQPage`. نودهای `WebPage` و `BreadcrumbList` همچنان از RankMath می‌آیند — این افزونه وقتی RankMath فعال باشد عمداً آن‌ها را تولید نمی‌کند تا موجودیت تکراری ساخته نشود.

### بررسی نتیجه

آدرس یک ویدئو را در [Rich Results Test](https://search.google.com/test/rich-results) بزنید. باید دقیقاً یک `VideoObject` ببینید، نه دو تا، و نه `Article` روی صفحه‌ی ویدئو.

## بازسازی ویدئوهای واردشده قبلی

اصلاحات نسخه ۱.۰.۳ (نامک تمیز، تصویر شاخص محلی، متن نوشته) روی import **جدید** اعمال می‌شوند. همگام‌سازی هم عمداً ویدئوی بدون تغییر را رد می‌کند، پس کتابخانه‌ی موجود شما خودبه‌خود اصلاح نمی‌شود.

**ویدئو هاب ← داشبورد ← بازسازی ویدئوهای موجود**

هر بار ۱۰ ویدئو را پردازش می‌کند تا روی هاست اشتراکی timeout نشود؛ پیام پایان تعداد باقی‌مانده را می‌گوید. تا وقتی «۰ باقی مانده» نشد دوباره بزنید. برای یک ویدئوی خاص، دکمه‌ی «بازسازی نامک، تصویر و متن» در پایین صفحه‌ی ویرایش همان ویدئو هست.

بازسازی محافظه‌کار است:

- **نامک** فقط وقتی عوض می‌شود که علامت نگارشی داشته باشد یا به‌طور محسوس بلندتر از شکل تمیز باشد. نامکی که خودتان کوتاه کرده باشید دست‌نخورده می‌ماند.
- **تصویر شاخص** فقط وقتی ست می‌شود که از قبل تصویری انتخاب نشده باشد.
- **متن نوشته** فقط وقتی نوشته می‌شود که خالی باشد یا قبلاً خود افزونه آن را نوشته باشد. متنی که خودتان تایپ کرده باشید هرگز بازنویسی نمی‌شود.

> تغییر نامک، آدرس ویدئو را عوض می‌کند. اگر ویدئویی از قبل در گوگل ایندکس شده یا جایی لینک شده، آدرس قبلی ۴۰۴ می‌شود — یک افزونه‌ی ریدایرکت (مثل Redirection) نصب کنید یا قبل از بازسازی نامک‌های فعلی را یادداشت کنید.

### چرا تصویر آپارات لود نمی‌شد

آپارات تصاویر پوستر را با بررسی هدر `Referer` محافظت می‌کند: تصویر در تب مرورگر باز می‌شود، ولی وقتی از دامنه‌ی دیگری embed شود ۴۰۳ می‌دهد. راه‌حل درست، مالکیت یک کپی محلی است — گزینه‌ی «تصویر ویدئو در کتابخانه رسانه ذخیره شود» همین کار را می‌کند و به‌صورت پیش‌فرض روشن است.

### چرا متن نوشته خالی بود

توضیحات ویدئوهای آپارات غالباً خالی است، پس `post_content` هم خالی می‌ماند. نمایش پنل‌های هوش مصنوعی در فرانت این را حل نمی‌کرد: آن‌ها هنگام نمایش ساخته می‌شوند و هرگز به محتوای ذخیره‌شده‌ای که RankMath تحلیل می‌کند نمی‌رسند — به همین دلیل ویدئوی کامل هم «محتوا کوتاه است» می‌گرفت. حالا خلاصه، نکات و سوالات به‌صورت HTML واقعی در متن نوشته ذخیره می‌شوند و پنل فرانت آن‌ها را تکرار نمی‌کند.

## شورت‌کد آرشیو کامل

```
[signteb_video_gallery]
```

یک صفحه بسازید (مثلاً «ویدئوها») و همین یک خط را داخلش بگذارید. تمام ویدئوهای بارگذاری‌شده با تیتر، توضیح کوتاه، مدت و موضوع نمایش داده می‌شوند — همراه با جستجوی زنده و فیلتر موضوعی.

تفاوتش با `[signteb_videos]`: پیش‌فرض‌هایش برای یک آرشیو کامل تنظیم شده — تا ۴۸ ویدئو در هر صفحه به‌جای ۱۲، و سبک `luxe` روی کارت‌ها.

### سبک luxe

حلقه‌ی رنگی که آرام دور کادر ویدئو می‌چرخد: در حالت عادی آهسته و کم‌رنگ، هنگام هاور سریع‌تر و پررنگ‌تر با درخشش ملایم. رنگ اصلی از تنظیمات افزونه و طلایی مکمل ثابت است.

روی هر شورت‌کد دیگری هم قابل استفاده است:

```
[signteb_videos style="luxe" per_page="9"]
[signteb_video_gallery style=""]          بدون حلقه، کارت ساده
```

سه ملاحظه در پیاده‌سازی رعایت شده: مرورگرهای بدون پشتیبانی `@property` نمی‌توانند زاویه را انیمیت کنند، پس به یک گرادیان ثابت و عمدی برمی‌گردند نه حلقه‌ی مرده؛ و `prefers-reduced-motion` چرخش را کاملاً متوقف می‌کند.

## هم‌نوع‌خواری کلمه کلیدی هنگام تولید مقاله

اگر مقاله‌ی تولیدی همان کلمه کلیدی صفحه‌ی ویدئو را هدف بگیرد، سیگنال بین دو آدرس تقسیم می‌شود: گوگل یکی را انتخاب می‌کند — معمولاً آن‌که شما نمی‌خواستید — و هر دو بدتر از یک صفحه‌ی واحد رتبه می‌گیرند. خود صفحه‌ی ویدئو اولین قربانی مقاله‌ای است که درباره‌ی همان ویدئو نوشته شود.

پیش از تولید مقاله، افزونه سایت را برای محتوای موجود روی همان کلمه کلیدی جستجو می‌کند و فهرست را به مدل می‌دهد با این قواعد:

- زاویه‌ی متفاوت بگیرد (تجربه‌ی بیمار، آماده‌سازی، مقایسه، پرسش‌های بعد از درمان)
- مطالبی که آن صفحات کامل پوشش داده‌اند را بازنویسی نکند، فقط اشاره و لینک بدهد
- حداقل به دو صفحه‌ی موجود لینک بدهد
- صفحه‌ی ویدئو مرجع اصلی آن کلمه کلیدی بماند و مقاله نقش مکمل داشته باشد

کلمه کلیدی از RankMath (یا Yoast) خوانده می‌شود؛ اگر تنظیم نشده باشد از عنوان تمیزشده استفاده می‌شود. برای کنترل دستی فهرست رقبا:

```php
add_filter( 'stvh_cannibalization_competitors', function ( $items, $post_id, $keyword ) {
    return $items;
}, 10, 3 );
```

## اگر سایت بعد از فعال‌سازی timeout داد

### علت

WP-Cron یک worker پس‌زمینه نیست. وقتی هاست درخواست loopback را مسدود کند — روی هاست‌های ایران و پشت Cloudflare رایج است — وردپرس رویدادهای سررسیده‌ی cron را **داخل درخواست یک بازدیدکننده** اجرا می‌کند. هر کاری که دقیقه‌ها طول بکشد، به صفحه‌ای تبدیل می‌شود که هرگز باز نمی‌شود.

تا نسخه ۱.۰.۶ بدترین حالت یک اجرا این بود:

| کار | زمان |
|---|---|
| دریافت آپارات (۲ درخواست × ۲۰s) | ۴۰s |
| دانلود تصویر (۳۰ ویدئو × ۳۰s) | **۹۰۰s** |
| صف هوش مصنوعی (۳ کار × ۹۰s) | ۲۷۰s |
| **مجموع** | **~۲۰ دقیقه** |

### راه‌حل فوری (اگر همین حالا سایت بالا نمی‌آید)

در `wp-config.php` قبل از خط `/* That's all */` اضافه کنید:

```php
define('DISABLE_WP_CRON', true);
```

سایت بلافاصله برمی‌گردد. سپس یک کرون واقعی سرور بسازید (بخش ۳-الف). اگر به `wp-config.php` دسترسی ندارید، پوشه‌ی `wp-content/plugins/signteb-video-hub` را از طریق FTP به `signteb-video-hub-off` تغییر نام دهید تا افزونه غیرفعال شود.

### راه‌حل دائمی (نسخه ۱.۰.۷)

- **بودجه‌ی زمانی:** هر کار پس‌زمینه یک سقف دارد (همگام‌سازی ۲۰s، هوش مصنوعی ۲۵s) و وقتی تمام شد تمیز متوقف می‌شود. باقی کار در اجرای بعدی انجام می‌شود — همگام‌سازی ذاتاً تدریجی است.
- **قفل اجرا:** دو اجرای هم‌زمان یک کار ممکن نیست. بدون آن، هر درخواست جدید همان کار کند را تکرار می‌کرد و سایتِ کند را به سایتِ از دسترس‌خارج تبدیل می‌کرد.
- **timeoutهای کوتاه‌تر:** دانلود تصویر ۳۰s ← ۸s، آپارات/یوتیوب ۲۰s ← ۱۲s، هوش مصنوعی ۹۰s ← ۴۵s.
- **کش وضعیت API:** پنل «وضعیت API» داشبورد دیگر هنگام باز شدن صفحه به aparat.com و googleapis.com درخواست نمی‌زند؛ اسنپ‌شات ۱۰ دقیقه‌ای می‌خواند. دکمه‌های «تست اتصال» همچنان زنده تست می‌کنند.

بدترین حالت از ~۲۰ دقیقه به **۴۵ ثانیه** رسید.

> اولین همگام‌سازی حالا چند اجرا طول می‌کشد تا همه‌ی ویدئوها بیایند. این عمدی است: چند اجرای کوتاه بی‌خطرند، یک اجرای طولانی سایت را می‌خواباند. برای پر کردن سریع کتابخانه، «همگام‌سازی دستی» را چند بار بزنید.

## وارد کردن فقط یک دسته (نسخه ۱.۰.۹)

به‌جای کل کانال، می‌توانید فقط یک **دسته از آپارات** یا یک **پلی‌لیست یوتیوب** را وارد کنید.

**ویدئو هاب ← تنظیمات ← منابع ویدئو**

۱. شناسه کانال را وارد و **ذخیره** کنید (بارگذاری فهرست‌ها به کانال ذخیره‌شده نیاز دارد، نه آنچه در فرم تایپ شده).
۲. دکمه‌ی **بارگذاری دسته‌ها** (یا پلی‌لیست‌ها) را بزنید — نام هر مورد با تعداد ویدئوهایش می‌آید، پرتعدادترین اول.
۳. یکی را انتخاب و ذخیره کنید.

«کل کانال» یعنی رفتار قبلی و پیش‌فرض است.

### نکته‌های رفتاری

- **ویدئوهای قبلی حذف نمی‌شوند.** تغییر فهرست فقط تعیین می‌کند از این به بعد چه چیزی وارد شود. اگر می‌خواهید ویدئوهای خارج از فهرست جدید بروند، از **ویدئوها** دستی حذف‌شان کنید.
- **اگر فهرست حذف یا تغییر نام داده باشد**، افزونه به کل کانال برمی‌گردد و در «آخرین خطاها» ثبت می‌کند — تا سایت با هیچ ویدئویی نماند.
- **آپارات و یوتیوب مستقل‌اند.** می‌توانید برای آپارات یک فهرست بگذارید و یوتیوب را روی کل کانال.

### چرا آپارات «دسته» است و یوتیوب «پلی‌لیست»

نسخه ۱.۰.۸ برای آپارات سراغ endpoint پلی‌لیست رفت و **کد ۴۰۵** گرفت — یعنی مسیری که حدس زده بودم وجود ندارد. چون از این محیط به aparat.com دسترسی نیست، نمی‌توانستم مسیر درست را پیدا کنم؛ و حدس دوم روی چیزی که قابل تست نیست، همان اشتباه را تکرار می‌کرد.

پس رویکرد عوض شد: دسته‌ها از **همان فهرست ویدئوهای کانال** استخراج می‌شوند که ثابت شده کار می‌کند. اگر ویدئوها وارد می‌شوند، دسته‌بندی هم کار می‌کند — به هیچ سرویس تازه‌ای وابسته نیست. این ضمناً دقیقاً همان چیزی است که خواسته شده بود: «دسته»، نه پلی‌لیست.

ترتیب تشخیص دسته: `cat_id` ← نام دسته ← اولین برچسب ویدئو. اگر هیچ‌کدام نبود، پیام صریح می‌دهد به‌جای فهرست خالی.

یوتیوب همچنان از `playlists.list` رسمی استفاده می‌کند و این ابهام را ندارد.

> برای یوتیوب، `playlists.list` فقط شناسه‌ی کانال (`UC…`) می‌پذیرد. اگر `@handle` وارد کرده باشید، افزونه اول شناسه را پیدا و یک روز کش می‌کند.

## فهرست پخش آپارات با آدرس (نسخه ۱.۱.۰)

اگر یک **فهرست پخش (playlist)** مشخص در آپارات دارید — مثل `https://www.aparat.com/playlist/1234567` — می‌توانید مستقیم آدرسش را بدهید:

**ویدئو هاب ← تنظیمات ← منابع ویدئو ← «یا آدرس فهرست پخش آپارات»**

۱. آدرس را از آپارات کپی و در این فیلد بچسبانید (شناسه‌ی خالی مثل `1234567` هم پذیرفته می‌شود).
۲. **ذخیره** کنید.
۳. دکمه‌ی **تست فهرست پخش** را بزنید و نتیجه را ببینید — این کار را *قبل از* همگام‌سازی انجام دهید.

اگر پر باشد، بر دسته‌ی انتخاب‌شده اولویت دارد. برای برگشتن به رفتار قبلی، فیلد را خالی کنید.

### صادقانه: این ممکن است روی سایت شما جواب ندهد

آپارات مستندات API عمومی ندارد و مسیری که در نسخه ۱.۰.۸ امتحان شد **کد ۴۰۵** برگرداند. از این محیط توسعه به aparat.com دسترسی نیست، پس نمی‌توانم مسیر درست را پیدا و تست کنم.

راه‌حل این است که کار پیدا کردن به سرور خودتان سپرده شود: افزونه چند مسیر محتمل را به‌ترتیب صدا می‌زند، اولین مسیری را که JSON قابل استفاده برگرداند نگه می‌دارد و یک هفته کش می‌کند. دفعات بعد مستقیم سراغ همان می‌رود.

سه حالت ممکن است:

| نتیجه‌ی «تست فهرست پخش» | یعنی |
|---|---|
| «فهرست پخش … خوانده شد» | مسیر پیدا شد، از این به بعد فقط ویدئوهای همان فهرست وارد می‌شوند |
| «هیچ‌کدام از مسیرها جواب نداد» | افزونه بی‌سروصدا به **فیلتر دسته** برمی‌گردد (همان روش تست‌شده)، سایت هیچ‌وقت بدون ویدئو نمی‌ماند |
| «از این آدرس شناسه‌ای پیدا نشد» | آدرس، آدرس فهرست پخش نیست — الگوی درست `aparat.com/playlist/{عدد}` است |

هر بار که همگام‌سازی به دسته برگردد، دلیلش در **آخرین خطاها** ثبت می‌شود.

**اگر جواب نداد و می‌خواهید حل شود:** صفحه‌ی فهرست پخش را در مرورگر باز کنید، `F12` ← تب **Network** ← فیلتر **XHR** ← صفحه را رفرش کنید. آدرسی که JSON ویدئوها را برمی‌گرداند همان چیزی است که لازم دارم؛ آن را بفرستید تا مستقیم به فهرست مسیرها اضافه شود.
